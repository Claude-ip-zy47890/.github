<p>把住宅 IP 接进内部系统批量开号之后，纯净度这件事就不能只靠"感觉挺干净"来判了。它得变成流程里的一道卡口：谁查、查哪几项、什么结果算过、记录存哪。更麻烦的是人员流动——今天负责这套流程的人走了，明天接手的人得能照着记录把环境复原，而不是从头再搭一遍。这篇从判定路径讲到记录规范，再给一次复原演练的做法，适合已经有内部开号系统的团队照着落地。</p>

<h2>一、先承认一件事：纯净度是相对的</h2>
<p>没有绝对干净的地址，只有"在这个时间点、对这个用途、风险足够低"的地址。理解这一点，流程才不会走偏。</p>
<h3>为什么必须相对看</h3>
<p>地址的历史由前手用户决定，你拿到时只能观测、不能改写。同一个地址，做轻量登录可能毫无问题，拿去高频批量操作就立刻显形。所以判定标准要和用途绑定，不能给一个通用结论。</p>
<h3>流程化的三个好处</h3>
<p>一是标准一致，不同的人查同一批地址得出同样结论；二是可追溯，出问题能回看当时查了什么；三是可交接，记录本身就是操作手册。这三条对团队比对个人重要得多。</p>

<h2>二、四条判定路径，可信度不一样</h2>
<p>纯度不能只看一个库。四条路径叠起来看，权重从高到低排列，结论冲突时以更严格的为准。</p>
<h3>路径一：归属与 ASN，权重最高</h3>
<p>whois 查 ASN、运营商名称、注册地。指向住宅宽带运营商的通过；指向数据中心、云服务、CDN 的直接判不过。这一项最难被伪造，也最稳定，所以放在第一位。</p>
<h3>路径二：情报库类型标签，作交叉验证</h3>
<p>主流 IP 情报库会给出 residential、business、hosting、proxy 等标签。至少查两个库，一致才可信；不一致时按更严的算。标签是长期观测结果，短期改不了，适合做第二道筛。</p>
<h3>路径三：滥用记录与黑名单，看近 90 天</h3>
<p>查公开的滥用投诉库，重点看最近三个月有没有批量注册、撞库、爬虫类投诉。有过投诉的地址，即便现在空着，也可能被持续降权。这一项对批量开号最关键。</p>
<h3>路径四：行为侧观测，最贴近实际</h3>
<p>用一个小号在这条线路上做三次正常登录，记录是否弹验证、页面是否完整、首屏耗时。这一项最接近真实体验，但样本小、易受时段影响，只作为辅助判断，不单独作为通过依据。</p>

<h2>三、判定要落到系统里，不能停在聊天记录</h2>
<p>内部系统批量开号，最容易出的问题是"查过了但没留痕"。三个月后没人记得当时查了什么，等于没查。</p>
<h3>把四道检查做成开号前置条件</h3>
<p>在开号流程里加一个校验步骤：地址入库时必须带四个字段——ASN、情报库结论、滥用记录结论、观测结论。缺任意一项，开号请求不通过。技术实现上就是一次必填校验，成本很低。</p>
<h3>结论要带时间戳和查询人</h3>
<p>同一个地址，三个月前查是干净的，现在未必。记录里必须写清查询日期和查询人，超过三十天的结论自动失效，需要重查。这条规则能挡掉大部分"拿旧结论当新结论"的问题。</p>

<h2>四、交接记录要能复原一套环境</h2>
<p>换人接手时最怕听到"这个我也不太清楚，之前是他弄的"。能不能复原，取决于记录里有没有这几样。</p>
<h3>环境三件套：出口、配置档、习惯</h3>
<p>出口地址写清当前值与备用值；配置档写清目录名和关键参数（时区、语言、UA 版本）；习惯写清常用登录时段与操作强度。三样齐全，新人照着就能重建一个几乎一致的环境。</p>
<h3>一份能照着走的交接清单</h3>
<p>清单不用长，但要能操作：账号编号、绑定出口、配置档路径、最后更新时间、当前状态（正常、观察中、暂停）、备注。交接时逐行过一遍，双方签字确认，比口头交接可靠得多。</p>
<h3>复原演练：一年做一次就够</h3>
<p>找一台干净机器，让接手人只凭记录重建一个账号的环境，全程不询问原负责人。能把环境跑起来、登录顺畅，说明记录合格；中间卡住的每一步，就是记录该补的地方。这项演练一次两小时，比任何文档评审都有效。</p>

<h2>常见问答</h2>
<h3>四个判定路径都要查吗，会不会太慢？</h3>
<p>答：批量开号建议全查，但可以并行。归属和情报库查询各几十秒，滥用库查询也快，行为观测最慢，可以放在开号后、放量前做。整体控制在十分钟内是可行的。</p>
<h3>情报库结论不一致时听谁的？</h3>
<p>答：按更严格的算。一个库标住宅、另一个标托管，就按托管处理，退回换地址。宁可换一条，也别拿"另一个库说没事"当理由放行，代价不对等。</p>
<h3>地址用了一个月还要重查吗？</h3>
<p>答：要。地址的历史会变，同段邻居的行为也会变。建议每三十天重查一次归属与滥用记录，观察结论每七天更新。重查成本低，出问题的成本高。</p>
<h3>交接记录需要写到多细？</h3>
<p>答：标准是"一个没接触过这个账号的人，只看记录就能把环境重建起来"。达不到这个标准就继续补，别指望口头交代能替代记录。</p>
